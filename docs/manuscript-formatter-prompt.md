# 저널 투고 양식 도우미 — 개발 프롬프트

아래 "프롬프트 본문"을 Claude Code(또는 다른 코딩 에이전트)에 그대로 붙여넣으면 프로그램을 처음부터 만들 수 있다.
그 아래 "정확성·편의성 제안"은 프롬프트에 이미 반영된 설계 원칙의 이유를 설명하고, 추가로 고려할 기능을 정리한 것이다.

---

## 프롬프트 본문

```text
# 목표
학술지 투고 규정(Guide for Authors)을 읽어 (1) 그 규정에 맞는 Word 원고 템플릿을 만들고,
(2) Figure의 해상도·크기·형식을 규정에 맞게 변환하고, (3) 사용자가 올린 원고의 "서식만" 규정에 맞게 바꾸고,
(4) 원고의 오타·오류를 목록으로 보여준 뒤 사용자가 승인한 항목만 고친 파일을 따로 만드는 로컬 웹 애플리케이션을 만든다.

# 기술 스택
- Python 3.11+, UI는 Streamlit (단일 사용자 로컬 실행: `streamlit run app.py`)
- 문서: python-docx (+ 필요 시 lxml로 OOXML 직접 편집)
- 투고 규정 입력: requests + BeautifulSoup(정적 HTML), Playwright(JS 렌더링 페이지), pdfplumber(PDF), python-docx(DOCX)
- Figure: Pillow(래스터), pypdfium2 또는 PyMuPDF(PDF/벡터 래스터화), CairoSVG(SVG), img2pdf(무손실 PDF 래핑)
- LLM: Anthropic Claude API (`anthropic` SDK). 규정 해석과 오타 탐지에만 사용하고,
  실제 문서 수정은 항상 결정적(deterministic) 코드로 수행한다. 모델 ID는 설정 파일에서 바꿀 수 있게 한다.
- 테스트: pytest

# 핵심 원칙 (반드시 지킬 것)
1. LLM은 "무엇을 해야 하는지"만 판단하고, 파일을 직접 쓰지 않는다. LLM 출력은 JSON 스키마로 검증한 뒤 코드가 적용한다.
2. 규정에 없는 값은 지어내지 않는다. 찾지 못한 항목은 "not_specified"로 두고 UI에 표시하며,
   기본값을 쓸 경우 "기본값 사용"이라고 명시한다.
3. 추출한 모든 규칙에는 근거(원문 인용 + 페이지/URL 위치)를 붙인다. 근거 없는 규칙은 적용하지 않는다.
4. 원고 서식 변환(기능 3)은 글자를 한 자도 바꾸지 않는다. 변환 전후 본문 텍스트가 동일한지 코드로 검증하고,
   다르면 결과 파일을 저장하지 않고 오류를 보고한다.
5. 원본 파일은 절대 덮어쓰지 않는다. 모든 결과는 새 파일로 저장한다.

# 기능 1 — 투고 규정 읽기 → Journal Profile
입력: URL, PDF, DOCX 중 하나 (여러 개 동시 입력도 허용: 예) 웹 규정 + 별도 PDF 체크리스트).

처리:
- URL: 먼저 requests로 시도하고, 본문 텍스트가 너무 적으면 Playwright로 렌더링한다.
  페이지 안에 "Guide for Authors", "Instructions for Authors", "Submission guidelines", "Artwork" 등의
  하위 링크나 PDF 링크가 있으면 목록으로 보여주고 사용자가 고른 것만 추가로 가져온다(같은 도메인, 최대 깊이 1).
- PDF: pdfplumber로 페이지 번호를 유지하며 텍스트·표 추출. 스캔 PDF(텍스트 없음)는 "OCR 필요"로 알린다.
- DOCX: 문단·표·머리글 순서대로 추출.
- 추출 텍스트를 섹션 단위로 나눠 Claude에 보내고, 아래 스키마의 JSON을 tool use(structured output)로 받는다.
  텍스트가 길면 나눠 보내고 결과를 병합하되, 같은 항목에 값이 충돌하면 둘 다 보여주고 사용자가 고르게 한다.

Journal Profile 스키마 (각 리프 값은 {value, source_quote, source_location, confidence} 형태):
- journal_name, article_types[] (유형별 단어 수 제한, 초록 길이, 그림/표/참고문헌 개수 제한)
- page: 용지 크기, 여백(상/하/좌/우), 방향
- text: 글꼴, 글자 크기, 줄 간격, 정렬, 문단 들여쓰기, 줄 번호(연속/페이지별), 페이지 번호 위치
- structure: 제목 페이지 구성 요소와 순서(제목, 짧은 제목, 저자, 소속, 교신저자, ORCID 등),
  필수 섹션 순서(Abstract, Keywords, Introduction, Methods, Results, Discussion, Conclusion,
  Acknowledgments, Funding, Conflict of Interest, Data Availability, References, Figure legends, Tables),
  구조화 초록 여부와 소제목, 키워드 개수, 제목 글자 수 제한
- headings: 단계별 서식(굵게/기울임/크기/번호 여부)
- references: 인용 방식(번호/저자-연도), 참고문헌 스타일 이름(예: Vancouver, APA 7, AMA)과 예시 원문
- tables: 위치(본문 내/원고 끝/별도 파일), 캡션 위치
- figures: 허용 형식, 최소 해상도(선화/사진/혼합 각각), 컬러 모드(RGB/CMYK), 폭(1단/1.5단/2단, mm),
  최대 높이, 최소 글자 크기, 파일명 규칙, 범례 위치(본문/원고 끝)
- other: 하이라이트, 그래픽 초록, 커버레터, 보충자료 등 제출 요구 사항

UI:
- 추출된 Profile을 표로 보여주고, 각 값 옆에 근거 원문을 펼쳐 볼 수 있게 한다.
- confidence가 낮거나 not_specified인 항목은 노란색으로 강조한다.
- 사용자가 값을 직접 수정·확정할 수 있게 하고, "확정" 버튼을 눌러야 다음 단계로 진행된다.
- 확정한 Profile은 `profiles/<저널명>.json`으로 저장하고 다음에 불러올 수 있게 한다.

# 기능 2 — Word 원고 템플릿 생성
- 확정된 Profile로 .docx를 생성한다.
- Word "스타일"(Normal, Title, Heading 1~3, Caption, Reference 등)을 정의하고 모든 문단이 스타일을 쓰게 한다
  (직접 서식 금지 → 사용자가 이후에 써도 서식이 유지됨).
- 여백, 용지, 줄 번호(sectPr lnNumType), 페이지 번호(필드), 줄 간격을 실제 OOXML 속성으로 설정한다.
- 섹션 순서대로 제목과 안내용 자리표시자를 넣는다. 예: "[Abstract — structured: Background/Methods/Results/Conclusions, max 250 words]".
  자리표시자는 회색 기울임 문자 스타일 "Placeholder"로 구분해 나중에 찾아 지우기 쉽게 한다.
- 원고 끝에 표/그림 범례 자리, 참고문헌 예시(규정의 예시 원문 그대로)를 넣는다.
- 별도로 "투고 체크리스트"(제출 파일 목록, 단어 수 제한 등)를 템플릿 마지막 페이지 또는 별도 파일로 만든다.

# 기능 3 — Figure 해상도·형식 변환
입력: PNG, JPG, TIFF, BMP, PDF, SVG, EPS(가능하면). 여러 파일 일괄 처리.
옵션(기본값은 Profile에서 가져오고 사용자가 수정 가능):
- 이미지 종류: 선화(line art) / 사진(halftone) / 혼합(combination) → 목표 DPI 자동 선택
  (규정에 없으면 일반적 기준 1000/300/600 dpi를 "기본값"으로 표시)
- 목표 폭: 1단/1.5단/2단(mm) 또는 직접 입력. 종횡비는 항상 유지.
- 출력 형식: PNG, PDF (둘 다 선택 가능)
- 컬러 모드: RGB / CMYK / Grayscale (CMYK는 PDF·TIFF에서만 의미가 있음을 안내)

처리 규칙:
- 픽셀 수 = 목표 폭(inch) × 목표 DPI 로 계산해 리샘플링(LANCZOS)한다.
- 원본 픽셀이 부족해 업스케일이 필요하면 반드시 경고한다:
  "DPI 숫자를 올려도 원본에 없는 세부는 생기지 않습니다. 가능하면 원본(벡터 또는 고해상도)으로 다시 내보내세요."
  업스케일 배율이 2배를 넘으면 기본적으로 진행 전에 확인을 받는다.
- 벡터 입력(PDF/SVG/EPS)은 PDF 출력 시 벡터를 유지하고(페이지 크기만 조정), PNG 출력 시 목표 DPI로 래스터화한다.
- PNG: dpi 메타데이터(pHYs)를 기록한다. 투명 배경은 옵션에 따라 흰색으로 평탄화.
- PDF(래스터 입력): 이미지를 재압축 없이 넣고, 페이지 물리 크기가 목표 폭과 정확히 일치하게 한다.
- 결과 검증: 출력 파일을 다시 열어 픽셀 크기, DPI, 물리 크기(mm), 컬러 모드를 측정해 표로 보여준다.
- 파일명은 Profile 규칙(예: Figure1.png)을 따르고 원본 파일명과 매핑표를 함께 제공한다.

# 기능 4 — 업로드한 원고를 투고 양식에 맞게 변환 (내용 불변)
허용되는 변경(서식만):
- 용지·여백·방향, 글꼴·크기·줄 간격·정렬·들여쓰기, 스타일 적용(제목 수준 인식 → Heading 스타일 매핑),
  줄 번호·페이지 번호, 머리글/바닥글 서식, 표·캡션 서식.

금지되는 변경(문자 변경):
- 글자 추가·삭제·치환, 문장/문단 순서 변경, 참고문헌 스타일 변환, 섹션 이름 변경, 제목 번호 텍스트 추가.
- 위 항목이 규정상 필요하면 자동 적용하지 말고 "규정 불일치 보고서"에 넣는다
  (예: "References 스타일이 APA인데 규정은 Vancouver", "Data Availability 섹션 없음", "초록 312단어 > 250단어").

구현 및 검증:
- 문단 텍스트는 run 단위로 유지한다. 서식을 바꿀 때 run을 합치거나 쪼개지 않는다
  (불가피하면 합친 결과의 텍스트가 동일한지 확인).
- 각주, 미주, 표 셀, 텍스트 상자, 머리글/바닥글, 수식(OMML), 필드 코드(EndNote/Zotero 인용), 하이퍼링크,
  변경 내용 추적, 메모, 이미지가 손상되지 않게 한다. 처리할 수 없는 요소는 건드리지 말고 보고한다.
- 내용 불변 검증: 변환 전후 문서에서 (본문+표+각주+머리글 등) 모든 텍스트를 순서대로 추출해 비교한다.
  공백 정규화 없이 완전 일치해야 하며, 이미지·수식·필드 개수와 해시도 비교한다. 하나라도 다르면 저장 중단.
- 결과: `<원본명>_formatted.docx` + 변경 보고서(적용한 서식 목록, 적용하지 못한 항목, 규정 불일치 목록).

# 기능 5 — 오타·오류 목록과 승인 후 수정
- 탐지 범위: 철자, 문법, 띄어쓰기, 구두점, 같은 용어의 표기 불일치(예: "COVID-19"/"Covid-19"),
  약어 첫 등장 시 정의 누락, 숫자·단위 표기(예: "5mg" → "5 mg"), 본문 인용과 참고문헌 목록 불일치,
  Figure/Table 번호 누락·중복·순서 오류, 본문과 표의 수치 불일치(가능한 범위에서).
- 결정적 검사(정규식·카운트: 번호 순서, 인용 대응, 단위 띄어쓰기, 중복 단어)와 LLM 검사(철자·문법·문맥)를 함께 쓴다.
- 각 항목은 {id, 위치(문단 번호/페이지 근사), 원문 문장, 문제 부분, 제안 수정, 이유, 범주, 확신도} 형식.
- 원고의 의미, 결과 수치, 결론, 저자의 문체는 바꾸지 않는다. 의미가 바뀔 수 있는 제안은 "확인 필요"로 표시하고 자동 선택하지 않는다.
  학술 용어·유전자명·약물명·고유명사는 오타로 단정하지 않는다(사용자 사전에 추가 가능).
- UI: 체크박스 목록(범주별 필터, 전체 선택/해제, 확신도 높은 항목만 선택). 각 항목에서 원문↔수정안을 비교해 보여주고,
  제안 문구를 사용자가 직접 고칠 수 있게 한다.
- "선택한 항목 수정 파일 만들기" 버튼을 누르면 `<원본명>_corrected.docx`를 만든다.
  수정은 Word "변경 내용 추적"(w:ins / w:del, 작성자 "Manuscript Assistant")으로 넣어 Word에서 하나씩 수락/거부할 수 있게 한다.
  옵션으로 변경 내용을 모두 반영한 깨끗한 파일도 함께 만든다.
- 검증: 수정 파일에서 변경 추적을 모두 거부했을 때 원본 텍스트와 완전히 일치하는지, 모두 수락했을 때
  승인한 항목 외에는 차이가 없는지 자동 확인한다.

# 개인정보·보안
- 미발표 원고를 다루므로 기본은 로컬 처리. LLM으로 보내는 텍스트 범위를 UI에 명시하고,
  API 키는 환경 변수(ANTHROPIC_API_KEY) 또는 .env에서만 읽으며 로그에 원고 본문을 남기지 않는다.
- URL 가져오기는 http/https만 허용하고, 업로드 파일 크기 제한을 둔다.

# 테스트 (모두 통과해야 완료)
- content_guard: 다양한 원고(각주, 표, 수식, EndNote 필드, 이미지, 한글/영문 혼용)에 서식 변환 후 텍스트 완전 일치.
- 템플릿: 생성된 docx를 다시 열어 여백·글꼴·줄 간격·줄 번호가 Profile 값과 같은지 확인.
- Figure: 출력 PNG/PDF의 픽셀 수·DPI·물리 크기(±0.1 mm)가 목표와 일치. 벡터 PDF 입력 → PDF 출력이 벡터로 유지.
- 변경 추적: 모두 거부 = 원본, 모두 수락 = 승인 항목만 반영.
- 규정 추출: 실제 저널 2~3곳의 규정 fixture에 대해 핵심 값(여백, 글꼴, DPI, 초록 단어 수)이 정답과 일치.
  LLM 호출은 녹화된 응답으로 대체할 수 있게 한다.
```

## 정확성·편의성 제안

### 정확성을 보장하기 위한 장치 (프롬프트에 반영됨)

| 위험 | 대책 |
|---|---|
| LLM이 규정을 잘못 읽거나 지어냄 | 규칙마다 원문 인용·위치를 붙이고, 근거 없는 값은 `not_specified`로 둔다. 사용자가 확인 화면에서 확정해야 다음 단계로 간다. |
| 서식 변환 중 원고 내용이 바뀜 | LLM이 아니라 코드가 서식을 바꾸고, 변환 전후 텍스트·이미지·필드를 완전 비교한다. 하나라도 다르면 저장하지 않는다. |
| 규정상 글자를 바꿔야 하는 항목 (참고문헌 스타일, 섹션 이름 등) | 기능 4에서 자동 적용하지 않고 "규정 불일치 보고서"로 분리한다. 기능 5처럼 사용자가 승인해야 반영된다. |
| 오타 수정이 의미를 바꿈 | 항목별 승인 방식에 Word 변경 내용 추적을 더해 Word에서 다시 검토할 수 있게 한다. 의미가 바뀔 수 있는 제안은 기본으로 선택하지 않는다. |
| "해상도 향상"에 대한 오해 | 업스케일로는 원본에 없는 세부가 생기지 않는다는 점을 경고하고, 2배를 넘는 업스케일은 확인을 받는다. 출력 파일을 다시 열어 측정값을 보여준다. |
| 웹 규정이 JS로 렌더링되거나 여러 페이지에 나뉨 | Playwright로 렌더링하고, 하위 링크와 PDF를 사용자가 골라 함께 읽게 한다. |

### 추가로 고려할 편의 기능

1. **저널 Profile 라이브러리**: 한 번 확정한 저널은 저장해 두고, 다음에는 저널 이름만 고르면 된다. 규정 페이지가 바뀌었는지(해시 비교) 알려주면 더 좋다.
2. **원클릭 투고 패키지**: 서식을 바꾼 원고, 변환한 Figure, 체크리스트, 커버레터 템플릿을 하나의 ZIP으로 내려받는다.
3. **투고 전 사전 점검 대시보드**: 단어 수, 초록 길이, 키워드 수, 그림/표 개수, 참고문헌 수를 규정과 비교해 ✅/⚠️로 보여준다.
4. **Figure 미리보기와 실제 크기 보기**: 지면 폭에 맞춘 미리보기로 글자가 너무 작지 않은지(예: 6 pt 미만) 경고한다.
5. **원고 재사용(재투고)**: 리젝 후 다른 저널로 낼 때 Profile만 바꿔 같은 원고와 Figure를 다시 변환한다. 두 저널 규정의 차이점도 보여준다.
6. **사용자 사전**: 전문 용어, 유전자명, 약물명, 기관명을 등록해 오타 오탐을 줄인다.
7. **참고문헌 스타일 변환(선택 기능)**: 글자가 바뀌는 작업이므로 기능 5와 같은 승인 + 변경 추적 방식으로만 제공한다. 가능하면 Zotero/EndNote 필드나 CSL을 이용해 처리한다.
8. **한/영 UI 전환**과 단계별 안내 위저드(규정 → 확인 → 템플릿/Figure/원고).
9. **개인정보 모드**: LLM을 쓰지 않는 "오프라인 모드"를 두어 결정적 검사(번호, 인용, 단위, 서식)만 실행할 수 있게 한다.

### 사용 전에 정해 두면 좋은 것

- **실행 형태**: 내 PC에서만 쓸 것인가(Streamlit 로컬, 권장), 연구실 사람들과 함께 쓸 웹 서비스인가(FastAPI + 로그인 + 파일 자동 삭제)?
- **LLM 사용 범위**: 미발표 원고 본문을 외부 API로 보내도 되는지 기관 정책을 확인한다.
- **대상 저널 샘플**: 자주 투고하는 저널 2~3곳의 규정과 실제 원고 1편을 테스트 데이터로 준비하면 정확도를 검증하기 쉽다.
